# 横向测评契约（冻结版 v0.1）

## 一句话
把**同一个确定性五步流水线**分别用「手写基线」与三家工作流引擎实现，在**同一台机器、
同一份语料、同一个检索器**上对照读数；所有读数可由第三方原样复跑。

## 方向与被测对象
- 方向：**智能体工作流**（agent workflow）。选择理由：与已交付的 #67 首轮
  （灵枢 / Mem0 / basic-memory，记忆系统方向）**被测对象完全不相交**。
- 被测方案（3 家，均为公开可得、可离线安装）：
  1. LangGraph（LangChain 官方图状态机）
  2. LlamaIndex Workflows（事件驱动工作流）
  3. txtai Workflow（任务管道）
- 基线：**手写顺序 Python**（无编排框架），同一份步骤函数。

## 工作负载（harness/workload.py 是唯一定义）
1. `load` 读语料 JSONL（200 篇合成文档，种子 20261014）
2. `index` 建 BM25 索引（rank_bm25，四家共用）
3. `retrieve` 40 条查询各取 top-5（并列时按 doc id 升序，保证确定性）
4. `verify` 只保留正文含全部查询词的命中
5. `emit` 写结果 JSONL

**正确性判据（M1）**：emit 产物 sha256 与基线**逐字节一致**。

## 读数项
| 编号 | 读数 | 取法 |
|---|---|---|
| M1 | 产物 sha256 与基线一致 | metrics.sha256_file |
| M2 | 构建成本：非空非注释行数 + 编排单元数 | metrics.loc |
| M3 | 冷启动 import 耗时；端到端 p50/p95/min（7 次，1 次预热） | metrics.timeit |
| M4 | 断点续跑：注入失败后恢复，已完成步骤是否重跑、产物是否仍正确 | 原始 stdout |
| M5 | 失败重试：瞬时失败 2 次后成功，尝试次数与产物正确性 | 原始 stdout |
| M6 | 并发扇出：40 条查询并发（4 线程）对串行的耗时比 | metrics.timeit |
| M7 | 可观测性：失败时错误文本是否点名步骤 | 原始 stderr/stdout |
| M8 | 依赖足迹：安装目录 du -sh；零 LLM 凭据下能否运行 | du / 运行证据 |

## 公平性规则（四家同条件）
- 同一 Python（/usr/bin/python3 3.12.3）、同一机器、同一份语料与查询、同一 BM25。
- 每家装在**各自隔离的 --target 目录**，互不污染；`PYTHONPATH` 显式指定。
- 计时**交替进行**（基线/方案轮换），报告 min 与 p50，不用单次读数。
- 能力**不支持就写不支持**（附源码行号或官方文档），不臆测、不代跑。

## 未测面（显式声明）
- **LLM 调用面未测**：本机 shell 无任何 LLM/API 凭据（`env | grep -iE 'key|token|secret|api'` 为空），
  三家引擎的 LLM 相关能力（工具调用、消息归约、人工中断等）**均未测**。
- 未测网络、未测分布式/多进程持久化后端、未测厂商托管服务。
