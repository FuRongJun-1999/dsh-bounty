# 测评方法论 v0.1 —— 智能体工作流方向的离线确定性横向测评

## 1. 一句话与范围
把**同一个确定性五步流水线**分别用「手写基线」与三家工作流引擎实现，在**同一台机器、
同一份语料、同一个检索器**上逐项对照读数。所有读数由脚本自动落盘，报告只引用原始文本。

- 方向：**智能体工作流**（agent workflow）。
- 被测方案（3 家）：LangGraph、LlamaIndex Workflows、txtai Workflow。
- 基线：手写顺序 Python（无编排框架），同一份步骤函数。
- 本方法只测**离线确定性面**；LLM 调用面未测（见 §8）。

## 2. 为什么是这个方向（与首轮不撞车）
#67 的首轮交付（`WASD258-jpg/lingshu` 的 `bench/review67`，commit `a0d337d1…`）被测对象为
**灵枢 / Mem0 / basic-memory**，属**记忆系统**方向。本件按「同方向 ≥3 家 或 三方向各 ≥1 家」
中「**同方向 ≥3 家**」的口径交付，方向选**智能体工作流**，与被测对象**完全不相交**：
本件三家均为公开可得、可离线安装的工作流编排引擎，与首轮三家无任何重叠。

## 3. 工作负载（唯一定义：`bench/cross_eval/harness/workload.py`）
1. `load` 读语料 JSONL
2. `index` 建 BM25 索引（`rank_bm25`，**四家共用**）
3. `retrieve` 每条查询取 top-5（并列按 doc id 升序，保证确定性）
4. `verify` 只保留正文含**全部**查询词的命中
5. `emit` 写结果 JSONL

语料与查询由固定种子生成，任何人重跑都得到同一份：
- 语料：`data/corpus.jsonl`，**200 篇**（种子 20261014，每篇 60–140 词）
- 查询：`data/queries.jsonl`，**40 条**（种子 20261015，每条 3 个词，取自某篇文档 ⇒ 有确定来源文档 `src`）
- 负载特性（工作负载自身性质，与实现无关）：来源文档落在 top-5 内的查询 **22/40**；
  `verify` 后 40 条查询共保留 **91** 条命中（平均 2.28 条/查询）
- **黄金产物**：`data/out_baseline.jsonl`，40 行，
  sha256 = `8454e1f355832b516ed47eb3d479ffa14aa8f93bfbef30c2378b4bafb90940bd`

## 4. 读数项
| 编号 | 读数 | 取法 | 原始落盘 |
|---|---|---|---|

## 5. 公平性规则
- 同一台机器、同一 Python（`/usr/bin/python3` **3.12.3**）、同一份语料与查询、**同一 BM25 实现**。
- 每家装在**各自隔离的 `pip --target` 目录**，互不污染；`PYTHONPATH` 显式指定。
- 计时由同一脚本（`harness/runner.py`）测量：1 次预热 + 7 次取样，报 min/p50/p95，不取单次读数。
- **能力不支持就写不支持**，并给出依据（源码行号或官方文档 URL）；不许用「自己写个循环」冒充引擎能力。
- 只测公开可得、可离线安装的方案；不测厂商托管服务；不采集任何隐私数据。

## 6. 复现步骤（第三方原样可跑）
环境：WSL Ubuntu 24.04，`python3` 3.12.3，`nproc`=16，无任何 LLM/API 凭据。
依赖安装（隔离目录，清华镜像；本机 pypi.org 直连与代理均不可达）：
```
python3 -m pip install --break-system-packages --target ~/dm/pylibs/base       -i https://pypi.tuna.tsinghua.edu.cn/simple rank_bm25
python3 -m pip install --break-system-packages --target ~/dm/pylibs/langgraph  -i https://pypi.tuna.tsinghua.edu.cn/simple langgraph
python3 -m pip install --break-system-packages --target ~/dm/pylibs/llamaindex -i https://pypi.tuna.tsinghua.edu.cn/simple llama-index-core
python3 -m pip install --break-system-packages --target ~/dm/pylibs/txtai      -i https://pypi.tuna.tsinghua.edu.cn/simple txtai
```
复跑（以基线为例，三家同形；`<name>` 取 `baseline`/`langgraph`/`llamaindex`/`txtai`）：
```
cd <repo>
export PYTHONPATH=~/dm/pylibs/base:~/dm/pylibs/<target>
python3 -X utf8 bench/cross_eval/harness/runner.py --impl bench/cross_eval/harness/baseline.py --name baseline --modes normal,resume,retry,sequential,parallel
```
预期耗时：基线整轮（5 模式 + 3 组计时）约 **1 分钟内**（本机实测单模式端到端 min 55.585 ms / p50 62.665 ms）。
输出：`raw/baseline_<mode>.txt`（逐模式原始文本）、`raw/baseline_out_<mode>.jsonl`、`raw/baseline_summary.json`。

路径口径：上面命令里的 `<repo>` = 你的 dsh-bounty 克隆根（本次测量机为 `/mnt/d/lingshu-memory-plugin/cross-eval-20261014`）。
`raw/*.sh` 与 `raw/*.py` 是当时逐字使用的脚本，它们用 `$(dirname "$0")/../../..` 或 `__file__` 自行定位克隆根，可直接复跑；
`raw/*.txt`、`raw/*.json`、`raw/*.jsonl` 是**原始日志（证据）**，其中出现的绝对路径属于测量机，未做改写。
交付物守卫（与 CI 同一条）：`python3 -X utf8 scripts/check_reviews.py`（14 条判据，退出码 0 全绿）＋
`python3 -X utf8 tests/test_check_reviews.py`（正向 1 条 ＋ 29 条定点变异 ＋ 判据面/点名自证）。

## 7. 基线读数（三家方案的对照面，本机实测）
```
RUN mode=normal ok=True
SHA 8454e1f355832b516ed47eb3d479ffa14aa8f93bfbef30c2378b4bafb90940bd golden=8454e1f355832b516ed47eb3d479ffa14aa8f93bfbef30c2378b4bafb90940bd match=True lines=40
TIMING normal {"min_ms": 55.585, "n": 7, "p50_ms": 62.665, "p95_ms": 84.687}
TIMING sequential {"min_ms": 46.087, "n": 7, "p50_ms": 54.883, "p95_ms": 73.168}
TIMING parallel {"min_ms": 44.601, "n": 7, "p50_ms": 53.518, "p95_ms": 70.991}
```
- M2：基线 `harness/baseline.py` **66** 行（`metrics.loc` 口径：非空非注释行；文件总行 77），
  `harness/workload.py` 95 行（`metrics.loc` 口径；文件总行 123）。两家实现同用该口径，不混用总行数。
- M4：基线**无检查点**，失败后整段重跑 `["load","index","retrieve"]`（`raw/baseline_resume.txt`）。
- M5：基线**无内建重试**，`attempts=3` 来自手写 `while` 循环（`CAPS.retry=false`）。
- M6：本负载为 **CPU 密集且受 GIL 限制**（BM25 打分在 Python 层），故基线的线程池扇出
  **没有收益**（parallel min 44.601 vs sequential min 46.087，差异在噪声量级）。
  ⇒ 本方法**不把「并发更快」当作引擎优劣判据**，只报耗时与正确性；凡报告里出现
  「并发带来加速」的结论，必须同时给出 `raw/*_runner.txt` 的 TIMING 原始行。
- M8：依赖足迹（`du -sh`）：`base` 70M、`langgraph` 72M、`llamaindex` 247M、`txtai` 5.6G。

## 8. 不适用条件
- 本方法**只对「确定性、无 LLM 调用」的编排面成立**；凡结论依赖模型输出质量（工具调用、
  消息归约、计划质量、人工中断）的场景，本方法**不适用**，不得据本件结论选型。
- 负载是 CPU 密集的本地检索，**不代表 IO 密集 / 网络等待型负载**下的并发表现。
- 单机单进程、`InMemory`/本地持久化后端；**不代表**分布式、多进程、托管后端。
- 计时只在本机（16 核 WSL）有效，绝对值**不可跨机比较**，只可同机对照。

## 9. 未测项与原因
- **LLM 调用面：未测**。原因：本机 shell 无任何 LLM/API 凭据
  （`env | grep -iE 'key|token|secret|api'` 为空），`pypi.org`/`huggingface.co` 亦不可达。
  三家引擎的 LLM 相关能力（消息归约、工具绑定、结构化输出、流式、人工中断）**均未测**。
- **网络面：未测**（无外部服务凭据）。
- **多进程/分布式持久化后端：未测**（如各家的 SQLite/Postgres/Redis checkpointer）。
- **角色扮演方向：未测**（不在本件范围）。
