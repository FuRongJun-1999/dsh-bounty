## 二 为什么记忆系统优先

### 2.1 记忆是**所有能力的前置**
检索、推理、协作、信任——**全部建立在「记得住、找得到、改得对」之上**。记忆层一旦不可信，上层一切读数都失去意义。

**本站已有的活证据**：
- **issue #7**：`verify(verdict="falsified")` 绕过 `forget` 的删除闸 ⇒ **任何带 verify 作用域的令牌调用一次，就能把一条记忆永久删掉，`restore()` 找不回来**，且**默认装机即可触发**、同时绕过权限闸与确认闸。
- **issue #9**：审核接受后 `valid_until` 丢失 ⇒ **过期记忆在约定截止时间之后仍被召回**。

⇒ 这两条都不是「某个功能坏了」，而是**底层语义不可信**。**判据**：任何上层能力的可信度，都以记忆层的正确性为前提。

### 2.2 行业用**资本**投票
见 §一。**判据**：外部第三方（投资人）用真金白银给这一层单独定价，且境内外的定价量级一致（千万–亿美元级融资／数亿元估值）。

### 2.3 本站已有**可复跑的实测收益**
| 来源 | 读数 |
|---|---|
| issue #2 | hmb 切B 证据保留 **17.6 → 29.6**（+68%）、块级命中 **62.7 → 72.2**；定点变异 **9/9** 精确命中 |
| issue #8 | locomo-zh-500 + 1 万干扰 hit@10 **0.076 → 1.00**、MRR@10 0.067 → **0.964** |
| issue #5 | 625 题 现值 **0.979** ／ 历史 0.927 ／ 变更链 0.982（零 LLM 判官） |
| issue #6 | 169 passed；**9/9** 定点变异被指定断言检出 |

**判据**：上表全部是**可复跑的读数**，不是主张。

## 三 为什么理论与算法"资源不限"

### 3.1 算法是**乘数**，不是加数
一份算法改进（如 #2 的 BM25 ＋ 精确块剪枝）**被所有下游复用**：边际成本 ≈ 0，边际收益 = 全站。
对比：一个业务功能通常只服务一个场景，收益封顶于该场景。
**判据**：同一份算法产物被 N 个下游调用 ⇒ 收益随 N 增长；1 个功能的收益不随 N 增长。

### 3.2 瓶颈在**算法层**，不在工程层
**issue #3** 是最好的例子：**判分链自身**有 3 处缺陷（静默通过／越权改判／除零崩溃）——**量具错了，所有评测结论都错**。它把红树守卫从 5/13 修到 13/13。
这类问题**只能靠理论与算法层解决**：工程手段无法发现「量具本身不可信」。
**判据**：审计／复现类交付（#3／#7／#10）的价值，来自它们**能证伪**上层结论——这是纯工程交付不具备的性质。

### 3.3 理论结论**可独立复算** ⇒ 验证成本低、可信上限高
- #5：**零 LLM 判官**、机械判分、可带 key 重跑；
- #2／#6：**定点变异自证**（9/9、9/9）；#7：3 条变异各自转红。
**判据**：能给出「**注入必失败 ⇒ 断言必红**」的产物，其结论可被任何人独立复算；反之，不可复算的结论只能被相信，不能被检验。
