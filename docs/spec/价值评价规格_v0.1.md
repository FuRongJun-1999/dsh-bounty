# 价值评价规格 v0.1（本站只做声誉分与价值评价 · 不涉金额）

> **一句话**：本站输出**两样东西**——① **声誉分**（可复算的贡献度量）② **价值评价**（可复算的价值向量）。**金额不进站**：不同使用者拿自己的资金与权重，在站外对同一份向量各自换算。
> **上游**：`docs/spec/贡献量化指标体系_v0.1.md`（指标向量与「公开」硬判据的设计源头）、`v0.4`（计分口径）。
> **本件性质**：把 v0.1 的设计**落到当前可跑的承载面**——新增项目归属与影响等级两个数据面，并把「价值向量」定义为**本站的输出契约**。

---

## 〇 定位与硬边界

| 是 | 不是 |
|---|---|
| 声誉分（客观、可复算、防刷、可降） | ❌ 金额、钱包、支付、链上概念 |
| 价值评价（项目归属 ＋ 影响等级 ＋ 证据强度，构成向量） | ❌ 折算系数、汇率、分配比例 |
| 让第三方**能算出同一个向量** | ❌ 让第三方**反推出某人的钱** |

**两条不可动的推论**：
1. **本站任何数据面里不存在金额字段**——包括标签、事件、账本、页面文案。金额只存在于使用者侧。
2. **本站不合成单一「价值分」**——合成需要权重，而**权重是使用者侧的决策**（记忆系统为核心的使用者与测评网站为核心的使用者，对同一贡献的权重不同）。本站给**原始维度**，合成交由使用者。

## 一 三层数据面

| 层 | 载体 | 写入者 | 现状 |
|---|---|---|---|
| **项目归属** | `project:*` 标签（`memory` / `bench_site` / `bounty_site` / `rpg` / `daily_test`） | 发布者或维护者 | **待加** |
| **声誉分** | 账本 `delta`（难度 × 质量化 ＋ 落选 ＋ 扣分） | 系统（唯一写入者，既有纪律） | **已有** |
| **价值评价** | `impact:*`（P0–P3）＋ 判定依据留痕 | 维护者（人审闸） | **待加** |

---

## 二 价值向量（本站的输出契约）

对每个「**贡献者 × 项目**」输出：

```
{
  project,             # 项目归属（project:* 标签）
  difficulty_base,     # 1 / 3 / 6 / 10（现有难度表）
  quality_E,           # 0..1（/verify partial 的通过率；未判定则 null）
  rounds,              # 0..2 已发生返工次数
  impact_grade,        # P0 / P1 / P2 / P3（人审，带依据）
  evidence_strength,   # 可复现读数与定点变异的有无（有/无）
  reputation_delta     # 已结算的声誉分（现有账本的求和）
}
```

**使用者侧折算（示例，本站不执行）**：
- 使用者 A（记忆系统为核心）：权重 `memory: 10，其他: 1`
- 使用者 B（测评网站为核心）：权重 `bench_site: 10，其他: 1`
→ **同一份向量，两人换算出不同的分配** ✓ 这正是「不同使用者有不同资金」的表达方式。

## 三 可复算判据（能红）

| # | 判据 | 可构造检验 |
|---|---|---|
| **V1** | **向量可复算** | 只给标签表 ＋ 事件表 ＋ 交付元数据，第三方手算某人的完整向量 → 必须与站内一致 |
| **V2** | **金额不可反推** | 全站 grep 金额/币种/汇率模式 → **零命中**；出现即越界（本站不得有任何金额字段或折算系数） |
| **V3** | **影响等级留痕** | `impact:*` 必须带判定人与依据；无依据的等级不可写入（否则价值评价不可追溯） |
| **V4** | **权重不固化** | 站内**不得**出现"某项目更值钱"的数值表达（如权重表、系数）——项目重要性只能由使用者声明，本站只记录归属 |

## 四 影响等级：**可配置的分级体系**（本次修订）

**设计原则**：**分级本身是机制，级别命名不是**。名称（S/A/B/C/D、甲乙丙丁、1–5…）、**档数**、**判据**全部由**一张常量表**决定——改口径只改表，全站（记账、看板、向量出口、文档）随之生效。这与难度表（`DIFFICULTY_SCORES`）同款：**口径单点**。

### 4.1 默认表（可替换）

```python
#: 影响等级表——**可调**：名称、档数、判据都由此决定；改口径只改这里。
IMPACT_GRADES = ("S", "A", "B", "C", "D")
IMPACT_CRITERIA = {
    "S": "不可逆损失或安全破坏，且默认配置即可触发",
    "A": "核心链路失效、语义错误，或量具失效（使评测结论不可信）",
    "B": "新系统交付、未合入的提案，或需特定路径才可触发的缺陷",
    "C": "文档、设计、优化建议",
    "D": "未定级（证据不足或待复验）",
}
```

### 4.2 判级原则
**按「不做会怎样」判，不按「做了多难」判**——难度已由 `base`（1/3/6/10）表达，影响等级回答的是**另一个问题**：这条交付若不存在，使用者会损失什么。

### 4.3 「可调」的三层含义（可红）
| 层 | 含义 | 检验 |
|---|---|---|
| **可换名** | 把 `S/A/B/C/D` 换成甲乙丙丁或 1–5 → 全站一致改名，无需改任何逻辑 | 改表后重新生成看板：等级标识随之变化，事件与分数不变 |
| **可增删档** | 从 5 档改为 3 档或 7 档 → 只改表长度 | 删除一档后，历史值不与新表冲突（未在表内的历史等级按原值保留，不做静默重映射） |
| **可改判据** | 改写某档的判据文本 → 只影响后续判定，不改历史事件 | 判据是**留痕的判定依据**，不是可回写的开关 |

**硬约束**：等级**只由判定产生、随事件留痕**；站内**不得**出现任何「等级 → 金额/权重」的换算，也不得把等级合成单一数字（合成属使用者侧）。

### 4.4 与难度档的关系
**难度档与影响等级互相独立**：一条 `easy` 难度的交付可以是 `S` 级影响（如一行代码导致的不可逆删除），一条 `expert` 难度的交付也可以是 `C` 级影响（如大型设计文档）。**两轴不可互相推导**——这正是「价值评价」不能被难度替代的原因。

## 五 与现有体系的关系

**不改**：难度表（1/3/6/10）／质量化（`max(1, round_half_up(base × 2E/(round+1)))`）／扣分（按行为类型）／落选分（0/1/2/4）／账本与对账断言——**声誉分口径一字不动**。
**新增**：`project:*` 标签面、`impact:*` 价值面、价值向量输出（board 页与 JSON 出口）。
**未决**：影响等级用「标签」还是「`/appraise` 命令」写入；向量的公开粒度（是否逐人公开）。
