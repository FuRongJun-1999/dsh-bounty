# 多席 · 团队 · 多项招标 —— 设计稿 v0.1（**待裁**）

> 背景：现模型是**单人独占租约**（holder 单值、bounty:claimed 一人）。这不适配两类真实需求：
> ①大型任务（如灵枢大脑迭代）本就是**多人并行**；②悬赏要允许**团队方案**与**多项方案招标**。

## 一、三条概念

| 概念 | 含义 | 载体 |
| --- | --- | --- |
| **席（seat）** | 一个可独立认领／交付／结算的工作单元 | 标签 bounty:slots-<N> 声明席位数（缺省 1） |
| **团队（team）** | 一席由多人共同持有（队长 ＋ 成员） | 认领载荷 /claim with @a @b |
| **多项招标** | 一次定标可产生多个中标席 | /select @a @b -- <理由> |

## 二、向后兼容

- slots 缺省 **1** ⇒ 既有流程**一字不改**（单人独占租约）。
- 全部新字段随 marker 继承；老 marker 缺字段时按缺省解释。

## 三、席位数

- bounty:slots-<N>：N ∈ [1, 64]；bounty:slots-any：不限席（内部记 MAX_SLOTS）。
- 标签是**声明面**（人读）；marker 是**权威面**。首认领前无 marker，故席位数只能由标签给。
- **并行语义**：每人独立租约、独立到期、独立超时回板。

## 四、团队

- /claim with @a @b ⇒ 队长 = 评论者，成员 = a, b。任一人可 /deliver /withdraw。
- **一人一席**：同一人不得同时占同一 issue 的两席（防重复计分）。
- 账本事件记 team: [...]；**计分归属队长**（v0.1 简化；分队内分配留待 v0.2）。

## 五、多项定标

- /select @a @b -- <理由>：多中标，各自成一席，各走验收四闸。
- 落标者仍按难度记落选分（0/1/2/4）；**0 分也写事件**。

## 六、态聚合

| issue 态 | 条件 |
| --- | --- |
| claimed | ≥1 席在办 |
| delivered | 无在办席 ∧ ≥1 席已交付 |
| settled | 全部席已结算 |

## 七、**明确不做**（v0.1 边界，诚实声明）

- **队内分账**：计分归队长，不做队内分配。
- **按席独立验收**：/verify /settle 仍在 issue 级（全部交付后一次性验收）。
- **席级申诉**：/dispute 仍按 issue。

## 八、待裁项

1. slots 缺省值：1（兼容）还是 3（更贴合「大型任务」）？
2. 团队计分：归队长 ／ 均分 ／ 队长得 base、成员得 base/2？
3. 多项招标的落选分：与单选一致（0/1/2/4）？
