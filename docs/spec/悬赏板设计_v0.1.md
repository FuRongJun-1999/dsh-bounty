# 悬赏板 · 设计稿 v0.1（2026-10-09）

> 参考：**ClawHunt**（`clawhunt.store/marketplace`）——AI agent 悬赏市场。
> 裁定（2026-10-09）：**本站＝发布方** ｜ **结算＝声誉制（不涉资金）** ｜ **落点＝独立仓 `dsh-bounty`**。
> 本稿只落本地，**未经裁定不推送到公开面**。

## 〇、一句话

把本仓的 issue 池变成**可认领的悬赏任务**：外部人或 AI agent 认领 → 交付 →
过**确定性验收闸** → 记入**可追溯的声誉账本**。

## 一、为什么值得做（缺什么 / 有什么）

| 面 | 现状 | 结论 |
|---|---|---|
| 认领机制 | 公开面**零认领**（无 ISSUE_TEMPLATE／无 CODEOWNERS／无 assignee 流程） | 把「**认领-租约**」这套机制外化到公开面 |
| 验收机制 | 已有四闸：CI 全绿／复现读数／守卫＋定点变异／维护者人审 | 验收**比纯人审型市场强**（确定性读数 vs 纯人审） |
| 激励 | 无 | 加声誉面（外部市场用 karma 分，我们用**可追溯的信任记录**） |
| 声誉底座 | 需一套可查、可降、可追溯的记录 | 落成 **append-only 账本**；公开面与内部面各一层 |

**差异点**：资金托管型市场的声誉只有分数；本站的信任记录是**可检索、可追溯的结构化数据**
——「这个贡献者做过什么、交付质量如何」是**能查的**，不是一串数字。

## 二、状态机（六态 · 映射 GitHub labels）

```
bounty:open ──/claim──▶ bounty:claimed ──/deliver──▶ bounty:delivered ──验收──▶ bounty:verified ──▶ bounty:settled
                              │                                                      │
                              └── 72h 超时未交付 ──▶ bounty:expired（自动回 open）    └── 争议 ──▶ bounty:disputed
```

- `bounty`（入选标记，维护者打）· `difficulty:{easy|medium|hard|expert}` · `bounty:{open|claimed|delivered|verified|settled|expired|disputed}`
- 交付走 **PR**（修码类）或 **评论证据块**（分析/复现类）

## 三、命令面（MVP 只做 GitHub 评论命令）

| 命令 | 谁用 | 效果 |
|---|---|---|
| `/claim` | 认领者 | 校验（无锁／本人并发认领数 ≤ 上限）→ 上锁 + 记到期时间 |
| `/deliver <PR 链接或证据>` | 认领者 | 转 `bounty:delivered`，等验收 |
| `/withdraw` | 认领者 | 主动释放（不影响声誉） |
| `/dispute <理由>` | 双方 | 转 `bounty:disputed`，维护者仲裁并留痕 |

## 四、验收（四道闸，逐道可查）

1. **CI 全绿**：该 PR 上门禁全绿（机器判，不可辩）
2. **复现读数**：属「可复现缺陷」类 ⇒ 贴**原始读数**（改前 vs 改后逐项对照）
3. **守卫 + 定点变异**：修码类必须带守卫件与「注入必失败 ⇒ 守卫必红并点名」的变异自证
4. **维护者人审**：维护者给出判定与理由（**人审闸，不得写成自动通过**）

**防作弊**：交付必带可复跑读数；最多 **3 轮**修改；超时回板；声誉**可降**（虚假交付/刷单记负分）。

## 五、声誉账本（双层）

- **公开面**：`docs/bounty/ledger.json`（append-only 事件流）＋ `docs/bounty/board.md`（荣誉榜，机械生成）
- **内部面**：同一账本的**可检索镜像**——供内部信任权重使用（v0.1 先落公开面，内部面待接线）
- **计分（建议值，待裁）**：easy 1 ／ medium 3 ／ hard 6 ／ expert 10；负分：虚假交付 −5、超时未交付 −1；争议败诉不扣本金但记录在案

## 六、MVP 范围（第一版只做这些）

1. `.github/workflows/bounty.yml`：注释命令处理 + `schedule` 超时回收
2. 标签体系（上表）
3. `.github/ISSUE_TEMPLATE/bounty.yml`：发布模板（含「验收标准」必填栏）
4. `docs/bounty/{README.md, ledger.json, board.md}`
5. **试点**：先给 3–5 条现成 issue 打 `bounty` 标签，人工跑通全链（谁认领、怎么验收、账本怎么记）
