## 三 计分口径（可复算）

```
Δ = max(1, round_half_up(base × 2 / (round + 1)))        # 舍入强制 half-up
round = 已发生的返工次数（首次交付 = 0）
```

### 3.1 为什么本表统一取 `round = 1`（**中性点**）

这 10 条是**自发提交**（本仓从无对应 `bounty` 任务 issue），**没有任务期限、没有轮次约定、且多数尚未验收**。  
因此：

- **不取 `round = 0`**：那是「**一次过闸**」的奖励（2×），而「过闸」意味着**已验收通过**——未验收即发 2× 等于**提前发奖**；
- **不取 `round = 2+`**：那是对返工的惩罚，而这批里只有 #8 有明确返工记录（维护者四条阻塞 → 返工闭环），已按 `round = 1` 计；
- **取中性点 `round = 1`** ⇒ `Δ = base`，与 v1.0 原分口径一致（**不奖不罚**）。

### 3.2 对照：若维护者判为「一次过闸」

**每条翻倍 ⇒ 总计 124 分**（差额 = 62）。即：把「未返工」确认为「一次过闸」是一次**加分**决策，请显式裁定，不默认给。

### 3.3 影响等级**不参与**本表计分

按《价值评价规格 v0.1》**V2/V4 硬约束**：影响等级与难度是**两条独立的轴**，站内**不合成单一价值分**、**不换算金额**。  
影响等级（尤其 #7 的 **S** 级 P0）由使用者在自己换算时加权——**站内给原始维度，不给结论**。
