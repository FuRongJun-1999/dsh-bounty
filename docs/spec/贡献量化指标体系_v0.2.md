## 〇、一句话

v1.0 的「完成即 `+base`」只承认**难度**，不承认**质量**；本版把结算口径锚在**发布者的验证成本**上——**用户多验一轮就少拿，少验一轮就多拿**，并**钉死三处会破坏可复算性的口径**（`round` 起点、`E` 的数据承载、与摊薄/折算的复合顺序）。

## 一、价值论依据：质量的量纲是「用户少付的验收代价」

发布者每接一次返工交付，就要**重新读证据、重新逐条验收** ⇒ 验收成本 ∝ `round + 1`。因此：

- **中性点＝1 轮返工**（"标准交付"），乘数恰为 1.0，即 `delta == base`。取 1 轮而非 0 轮，是为了让 v1.0 的**等级阈值 `T(n)=10×n(n−1)/2` 与权益 `max_concurrent_tasks` 不被隐性下移**（它们按 1/3/6/10 标定）。
- **0 轮是奖励**（用户一次验完，成本减半），**3 轮是代价**（用户验收成本翻倍）。
- **无效交付的损失**（时间窗口与机会成本）**已由 v1.0 `−base` 覆盖**，本版不重复计价。

## 二、修订公式

```
delta = max(1, round_half_up(base × 2 / (round + 1)))          # 本版口径（E ≡ 1）
delta = max(1, round_half_up(base × 2E / (round + 1)))         # E 启用后（待裁，见 §四·问题2）
```

| `round` | 乘数 | expert | hard | medium | easy |
|---|---|---|---|---|---|
| 0（一次过闸） | 2× | 20 | 12 | 6 | 2 |
| 1（标准·中性点） | 1× | 10 | 6 | 3 | 1 |
| 2 | 2/3 | 7 | 4 | 2 | 1 |
| 3（上限） | 1/2 | 5 | 3 | 2 | 1 |

> 乘数列**仅供阅读**，定义式一律以 `2/(round+1)` 为准——写成 `0.67×` 会在 `base` 改动后漂移（复核指出）。

### 2.1 三处口径钉死（复核拦下的缺口，逐条闭合）

**① `round` 语义**：定义为「**已发生的返工次数；首次交付＝0**」。
- **证据**：v1.0 中 `claim.round DEFAULT 1`、`submission.round` 是"第几轮交付"；若按 1 起算，`round+1=2`⇒首轮只有 0.5×，而 **2× 奖励永不可达**。
- **落码口径**：`round := submission.round − 1`（或独立返工计数字段导出），**并把该值写进 `ReputationEvent` 的 `formula` 快照**，使复算者不必猜。

**② 复合顺序**：钉死为「**先质量化 → 再摊薄 → 最后 `max(1,·)`**」。
- **证据（复核给出的双解反例）**：hard、`round=2`、团队 `n=3`（摊薄系数 0.6）——先质量化再摊薄＝`round(6×2/3)=4 → 4×0.6=2.4→2`；先摊薄再质量化＝`round(6×0.6)=4 → 4×2/3≈2.67→3`。**同一笔数据两个复算者得 2 与 3**。
- **落码口径**：中间态（质量化后的值、摊薄系数）一并写进 `formula` 快照。

**③ 舍入**：**强制 `round_half_up`（如 `floor(x+0.5)`），禁用语言内置 `round`**。
- **证据**：内置 `round` 多为银行家舍入。本版 `E≡1` 时唯一的 `.5` 情形（medium/`round=3`＝1.5、easy/`round=3`＝0.5）**恰好被 `max(1,·)` 兜住**，故当前无实质分歧；但**一旦启用 E，分歧立刻出现**——复核给出的两组回归用例：`base=10,E=0.25,round=1 → 2.5`（half_up 3 / 内置 2）、`base=10,E=0.9,round=3 → 4.5`（half_up 5 / 内置 4）。**这两条须写进测试**，否则将来有人"顺手简化"成 `round()` 会静默改分。

### 2.2 保底与不越界

`max(1,·)` 保证正分不为 0；**无效交付仍走既有 `−base`，不叠加质量扣减**（不双重惩罚）；单任务负向总额 ≤ `base`；超时 `−max(1, base//2)` 与 `admin_adjust`（必填理由）**均不动**。

## 三、与 v1.0 的关系：改了什么、没改什么

**改了（仅一条）**：「完成即 `+base`」⇒ 改为 §二的质量化公式。

**没改（逐条点名）**：`base` 1/3/6/10；团队摊薄；落选分 1/2/3/4；阶段折算；超时 `−max(1,base//2)`；无效交付 `−base`；**发布者不能单次扣分**（退回返工不扣分、只计轮次，上限 3 轮）；不产生声誉的事件清单；**系统唯一写入**；幂等与 `user.reputation_total == sum(events.delta)` 对账断言。质量化只改 `delta` 的**取值**，不改**写入纪律**。

## 四、复核处置表（独立复核判 DEFER；逐条处置如下）

| # | 复核发现（现象 + 证据） | 处置 |
|---|---|---|
| 1 | **`round` 起点未声明**——v1.0 `claim.round DEFAULT 1`，公式中性点在 `round=1`；口径二义，整表可能错位一档，2× 或永不可达 | **已闭合**（§二·2.1①）：钉死为"返工次数，首交付＝0"，落码 `submission.round − 1`，并进 `formula` 快照 |
| 2 | **`E` 无条目级数据承载**——`tasks_claimmilestone.status` 只有里程碑级枚举，`acceptance_criteria` 是文本数组；**第三方拿三张表算不出 E** | **本版降级为 `E ≡ 1`**（公式与表按 §二 收口）。E 的启用**前置**＝新增条目级判定表（claimmilestone × criteria key × pass/fail）；**属待裁**（见 §五·3） |
| 3 | **复合顺序未定**——hard/`round=2`/`n=3` 同一输入双解 2 与 3，摧毁 O1 可复算与 O2 对账 | **已闭合**（§二·2.1②）：钉死「先质量化 → 再摊薄 → 最后 `max(1,·)`」 |
| 4 | **落选分未同步缩放**——完成分最高放大到 2×，落选分仍 1/2/3/4 ⇒ hard 3 轮完成(3) == hard 落选(3)、medium(2)==(2)、easy(1)==(1)，"多轮返工后通过"与"提交后落选"同分 | **待裁**（§五·1）：复核建议重标落选分（如压缩为 `⌈落选分/2⌉`）以保证任一难度下 `round=3` 完成 > 落选。**本版不改 v1.0 已定值**，列为裁定项 |
| 5 | **`max(1,·)` 使 E 在 easy 档失效**——easy/`round=1` 时 E=1 与 E=0.5 同为 1，最直接的"减少用户损失"信号在最常见档位无作用 | **本版不阻塞**（E≡1）；E 启用时须一并裁定低 `base` 档的处理（声明该档 E 不生效，或改记账粒度——后者与整数账本冲突） |
| 6 | **扣分基数未随奖励同步**——一次过闸 `+2base`，无效交付仍 `−base`，相对威慑被稀释 50% | **待裁**（§五·2）：**保持不动亦可，但须写明是有意为之**，避免被读作疏漏 |

> 复核者自述边界（保留）：① 未直读 v1.0 与 v0.1 原文（子代理读权限受限），复核 3 基于取证摘要；② 撰写稿 `result.json` 返回被截断约 2037 字符，"没改什么"清单未取全；③ 存量账本按新口径回放的分值位移**未实算**。**凡涉及原文措辞的判定，若原文与转述不符则作废。**

## 五、待使用者裁定

1. **落选分是否重标**（复核发现的问题 4；不重标则"3 轮返工通过"与"落选"在 hard/medium/easy 三档同分）。
2. **扣分基数是否同步放大**（问题 6；保持不动亦可，但须显式声明为有意为之）。
3. **是否启用 E**（问题 2）：启用须先扩数据模型（条目级判定表）；不启用则本版公式即为完整口径。
4. **等级阈值是否重定标**：质量化使分数量级上移（一次过闸 2×，例：原需三次 expert 完成才够 `T(3)=30`，新口径两次即 40）。(a) 阈值同步抬高；(b) 阈值不动、接受温和通胀并观察。**不选等于默认 (b)**，故须显式裁定。
5. **存量迁移口径**：既往按 `base` 入库的事件**不回改**（append-only）；新口径只对新事件生效，须在 rules 页**明示生效时刻**，否则第三方复算必红。

## 六、能红判据（本版新增/保留）

| # | 判据 | 可构造检验 |
|---|---|---|
| R1 | 中性点不变 | 构造 `round=1, E=1` 的四档结算 → **必须等于 v1.0 原分**（1/3/6/10）；不等即中性点漂移 |
| R2 | `round` 语义 | 构造"首次交付"的结算 → `round` 快照**必须为 0**、乘数 2×；若为 1 即语义错位（2× 永不可达） |
| R3 | 复合顺序 | 构造 hard/`round=2`/团队 `n=3` → 两个复算者**必须都得 2**；出现 3 即顺序未钉死 |
| R4 | 舍入 | 启用 E 后跑两组回归用例（`2.5`、`4.5`）→ **half_up 与内置 round 必须不同且取 half_up**；相同即被"简化"回内置 |
| R5 | 质量方向 | 0 轮 vs 3 轮（四档，E=1）→ 前者**严格更高**；出现持平即质量维度失效 |
| R6 | 可独立复算 | 只给公开数据（`base`、`round`、规则常量）→ 第三方**能**算出同一 `delta`；若须读内部私有中间态即不满足公开 |
| R7 | 对账 | `user.reputation_total == sum(events.delta)`，`recalc_stats` 独立复算；重复投递不重复计分 |
