# 贡献量化指标体系 v0.3（三项裁定落地 · 定稿）

> **本件性质**：v0.2 的裁定落地版。使用者 2026-10-11 裁定：**① 落选重标；② 扣分基数同步放大；③ 启用 E**。
> **上游**：`docs/spec/悬赏站设计_v1.0.md` §4.4.6 · `docs/spec/贡献量化指标体系_v0.2.md`（本件取代其待裁口径）。
> **本版来源**：编排侧立式 → **蜂巢独立复核判 DEFER**（拦下 P1–P7 七项，含三处实质缺陷）→ 编排侧逐条处置 → 定稿。**复核发现全部保留在 §五**。

## 〇、三项裁定落地后的完整口径

| 项 | v1.0 原口径 | **v0.3（本版）** |
|---|---|---|
| 完成分 | `+base` | `max(1, round_half_up(base × 2E / (round + 1)))`（质量化 + 启用 E） |
| 落选分 | 1／2／3／4 | **0／1／2／4**（重标） |
| 无效交付 | `−base` | **`−2base`**（同步放大；**已知反证见 §四·3**） |
| 超时未交付 | `−max(1, base//2)` | **`−max(1, base)`**（同步放大） |
| 单任务负向总额 | ≤ base | **≤ 2base** |
| E | 无 | **启用**（前置＝判定表 + **声明快照**，§三） |

## 一、落选分重标：1／2／3／4 → **0／1／2／4**

**推导式**：`落选分(d) = min(旧落选分(d), 完成分(d, round=3, E=1) − 1)`

| 难度 | 旧落选 | 完成分（`round=3, E=1`） | **新落选** | 判据 |
|---|---|---|---|---|
| easy | 1 | 1 | **0** | 1 > 0 ✓ |
| medium | 2 | 2 | **1** | 2 > 1 ✓ |
| hard | 3 | 3 | **2** | 3 > 2 ✓ |
| expert | 4 | 5 | **4** | 5 > 4 ✓ |

**重标范围（复核 P1 修正后的准确表述）**：本重标保证 **`E = 1` 时**四档「`round=3` 通过 严格优于 落选」，**档内**无持平无倒挂（16 格全扫）。**它不保证 `E < 1` 时的严格性**——见 §四·1，那不是缺陷而是价值论的直接推论。

**边界**：
- easy 落选 **0 = 不发分**，但**必须仍写一条带类型的事件**（`delta=0`, `kind=lost_bid`），否则与「认领后什么都没交」在账本上同形，重标不可观测（复核 P1 补的要件）。
- 0 的语义是「**低于任何 `E=1` 的通过交付**」，不与 v1.0「落选分只在提交过有效交付时发放」冲突；保序仍成立：四档落选 ≥ 0 > 对应档超时 `−max(1, base)`（「交过」优于「弃权」）。
- 跨档持平保留（如 expert 落选 4 = hard `round=2` 完成 4）——这是**难度阶梯的固有性质**，非倒挂。

## 二、扣分基数同步放大

| 项 | v1.0 | **v0.3** |
|---|---|---|
| 无效交付 | `−base` | **`−2base`** |
| 超时未交付 | `−max(1, base//2)` | **`−max(1, base)`** |
| 单任务负向总额上限 | ≤ base | **≤ 2base** |

**对称基准（如实声明）**：本放大是**与奖励上限 `2base`（`round=0`）对齐**，**不是**与中性点交付（`round=1` 时 `= base`）对齐。因此在中性点交付上，扣分相对强度为 **1:2**；在 `round=3` 的低质量通过上可达 **1:4**。此为使用者裁定的直接后果，**§四·3 记录了复核给出的反向激励证据与本版的处理建议**，若认为不可接受请改裁。
**未改**：发布者不能单次扣分（退回返工不扣分、只计轮次）；`admin_adjust` 必填理由；不产生声誉的事件清单；系统唯一写入；`ReputationEvent` 唯一约束与 `reputation_total == sum(events.delta)` 对账断言。

## 三、启用 E：数据模型扩展与口径

### 3.1 前置（v0.2 复核问题 2 的根因）
v1.0 现状算不出 E（`tasks_claimmilestone.status` 仅里程碑级枚举、`acceptance_criteria` 为文本数组）。**启用 E 必须新增条目级判定表，且必须带"声明快照"**——否则分母不可复算（复核 P2）。

### 3.2 新增表 `tasks_criteriareview`（对齐 v1.0 §3.3 表风格）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGSERIAL | PK | |
| `claim_id` | BIGINT | FK → claim, NOT NULL | |
| `milestone_id` | BIGINT | FK, NOT NULL | |
| `criteria_key` | VARCHAR(64) | NOT NULL, **规范化**（trim + 大小写折叠后存储） | 与发布时声明条目一一对应 |
| `declared_count` | SMALLINT | NOT NULL | **结算时刻的声明条目数快照**（分母，落账后冻结） |
| `verdict` | VARCHAR(10) | NOT NULL | `pass` / `fail` / `undecided` |
| `comment` | TEXT | | 判定说明（公开面披露粒度另裁） |
| `reviewed_by` / `reviewed_at` | — | | |

**约束**：`UNIQUE(claim_id, milestone_id, criteria_key)`（键已规范化，防 `k`／`k `／`K` 变体绕过，复核 P5）；`CHECK(verdict IN ('pass','fail','undecided'))`。
**冻结（复核 P6）**：**结算后本表该 `claim_id` 的行不可变**；确有更正须走 `admin_adjust` 追加事件，不得原地改 `verdict`——否则复算 E 与原 `delta` 不一致，对账断言必红。
**聚合粒度（复核 P4c）**：`E` **逐里程碑结算**（与 `tasks_claimmilestone` 同粒度），每个里程碑各自产生一笔事件，**不做跨里程碑合并**；`declared_count` 为该里程碑的声明条目数。

### 3.3 E 的定义
- `E = 该里程碑 pass 数 / 该里程碑 declared_count`（皆计数，可独立复算）。
- `undecided` **按未通过计**（保守）；被扣方可走 v1.0 既有争议通道；判定覆盖率随事件公示。
- `declared_count = 0` ⇒ `E = null`。

### 3.4 `E = null` 的口径（**复核 P3 修正：按 `E = 0` 计**）
`E = null` 时 **按 `E = 0` 计算**（`delta = max(1, …) = 1`，即正分下限），并打 `quality_unverified = true`、不进质量榜。
**理由（复核的可构造证据）**：若按 `E = 1` 计，`base=6, round=1` 时——不声明条目 **+6** > 声明 2 条通过 1 条 **+3** > 声明全 fail **+1** ⇒ **不声明条目严格支配"声明但未全通过"**，且发布者（省事）与交付者（拿分）利益一致。按 `E = 0` 计后该支配消失（1 < 3 < 6）。
**发布侧义务**：发布任务时**必须**声明至少 1 条可复核验收条目（v1.0 §1.4 已抄「验收标准结构化」）；`E = null` 只应出现在历史数据与模板未覆盖入口。

### 3.5 easy 档的 E 分辨率（复核问题 5 的诚实处置）
easy 在 `round = 0` 时 E 有效（`E=1→2`、`E=0.5→1`）；`round ≥ 1` 时被 `max(1,·)` 吃掉。**这是整数账本 + 保底的必然，不是缺陷**——显式声明，不假装解决；若要求该档有分辨率，须改记账粒度（另行裁定）。

### 3.6 舍入（强制）
`round_half_up`（`floor(x+0.5)`），**禁用语言内置 `round`**。启用 E 后分歧立刻可达，两组回归用例：`base=10,E=0.25,round=1 → 2.5`（half_up 3／内置 2）、`base=10,E=0.9,round=3 → 4.5`（half_up 5／内置 4）。

## 四、复核发现的反证与本版处置

### 4.1 P1：落选重标与 E 联立后不再严格 —— **重新定性，不改公式**
复核给出的可构造输入：**声明 3 条、2 条 pass（`E=2/3`）、`round=3`** ⇒ medium 1（持平落选 1）／hard 2（持平 2）／**expert 3 < 落选 4（反转）**。解析阈值：medium 仅 `E=1` 严格、hard 需 `E≥5/6`、expert 需 `E≥0.9`。

**处置：不修改公式，改为显式定性 + 判据修正。** 理由（按使用者的价值论）：`E=2/3` 且 `round=3` 意味着「发布者验了 4 轮、声明 3 条里废了 1 条」——**这个交付给用户造成的损失，不低于"未被采纳"**（落选者至少不再占用发布者的后续验证时间）。故「极低质量通过 ≤ 落选」是**价值论的正确表达**，而非激励倒挂。
**判据修正**：R8 限定为 **`E=1` 时的档内严格**；新增 **R8b**：构造 `E=2/3, round=3` 的 expert 交付 ⇒ 必须 **≤ 落选分**（若反而高于落选，说明保底口径被误改）。

### 4.2 扣分基准与方向（P4）—— 按裁定落地，高亮风险
复核证据：medium `round=1`（中性点）`+3` vs 无效 `−6` = **1:2**；expert `round=3, E=0.5` `+3` vs `−20` ≈ **1:6.7**。**更值得注意的方向问题**：无效交付（**努力过**）`−2base` 重于超时未交付（**未努力**）`−base`，expert 差 10 分 ⇒ 预计失败时理性主体**更愿耗到超时**；叠加落选 `+4`，同一份"交过东西"的交付因判定归属不同（显式判无效 vs 有效但落选）可差 **24 分**。
**处置**：按使用者裁定执行（`−2base`／`−max(1, base)`），**不擅自改回**；本版如实记录上述反证，并**列为待确认项**（§六·1）。若使用者认为反向激励不可接受，可选：无效交付改回 `−base`（与中性点对称）或 `−1.5base`。

### 4.3 其余四项（已直接落入 §三）
- **P2 分母不可复算** → 判定表加 `declared_count` 结算快照 + 冻结（§3.2）。
- **P3 `E=null` 支配策略** → 改为按 `E=0` 计（§3.4）。
- **P5 键变体绕过** → `criteria_key` 规范化 + `CHECK`（§3.2）。
- **P6 verdict 可变 vs append-only 冲突** → 结算后冻结，更正走 `admin_adjust` 追加（§3.2）。
- **P7 阶段折算与摊薄的相对权重被动腰斩 + 复合顺序缺项** → 复合顺序沿用 v0.2 的钉死口径「**先质量化 → 再摊薄 → 最后 `max(1,·)`**」（本节重申，防遗漏）；**阶段折算 `max(1, round(base×ratio/100))` 不随 2× 放大**，故其相对占比下降（例：expert `ratio=50` 时由 50% 降至 25%）——**这是有意为之**：阶段分承认"完成了一半"，而质量化奖励的是"做得干净"，两者不应同比例膨胀。

## 五、能红判据（v0.3 定稿版）

| # | 判据 | 可构造检验 |
|---|---|---|
| R8 | 落选重标（**限 `E=1`**） | 四档构造「`round=3, E=1` 通过」与「落选」→ 通过**严格更高**；持平即重标失效 |
| R8b | 低质量通过可劣于落选（**有意为之**） | 构造 `E=2/3, round=3` 的 expert 交付 → **必须 ≤ 落选 4**；高于即保底口径被误改 |
| R8c | 0 分事件存在性 | easy 落选 → 账本**必须有** `delta=0, kind=lost_bid` 事件；缺失则该档重标不可观测 |
| R9 | 扣分放大生效 | `round=0` 时 `+2base` 与 `−2base` 绝对值相等；`round≥1` 时不对称是**已知取舍**，不得当作 bug 修 |
| R10 | E 可算 | 只给三张表（submission／milestone／**criteriareview 含 declared_count**）→ 第三方**能**算出 E；算不出即分母仍缺 |
| R10b | 冻结 | 结算后尝试改 `verdict` → **必须被拒**（或产生新事件而非原地改）；能原地改即对账必红 |
| R11 | `E=null` 不支配 | `base=6, round=1`：不声明条目（1）**必须 <** `E=0.5`（3）**<** `E=1`（6）；出现 `null > 0.5` 即支配策略复活 |
| R12 | 键规范化 | 构造 `k`／`k `／`K` 三条判定 → **必须撞 UNIQUE 被拒**；能写入即分子可刷 |

## 六、仍未裁定（3 项）

1. **扣分方向（§四·2）**：是否接受「无效交付（努力过）重于超时（未努力）」与 24 分判定权杠杆？接受则本节即定稿；若否，请指定改裁值（`−base` 或 `−1.5base`）。
2. **等级阈值是否重定标**：质量化使分数量级上移、落选分下调、扣分放大三者叠加 ⇒ Lv 推进速度改变。(a) 同步抬高；(b) 不动、接受温和通胀并观察。**不选等于默认 (b)**。
3. **存量迁移生效时刻**：既往事件不回改（append-only）；须在 rules 页明示分段生效时刻，否则第三方复算与对账必红。
