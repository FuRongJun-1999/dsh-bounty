结论

逐项指回读数：①「可验证性 3」：证据 1、2 给出的是命令入口而非读数——能跑，但 README 不公开任何量化对照组（无基线 vs 方案对照、无 hit@k、无 token 预算读数），故不给更高分；也不给 1，因 pnpm verify 本身是一套可复现的机械验证套件（与「没有对照读数」是两件事）。②「隐私与本地性 3」：README 明确「Local by default with Mnemon Native」，但同时列出多家第三方 Provider，并声明「Third-party Providers use their own services and scopes」——数据是否出本地取决于所选 Provider，故给中档。③「记忆持久 4」：三层记忆结构（Runtime memory／Project Documents／Memory Spaces）＋ ZIP 备份口径在 README 里有明确描述。④「检索质量 1」与「注入预算 1」＝无读数档：README 未提供该两维度的任何读数（见 unmeasured_dims）。

边界 · 不适用条件

不适用条件：①本条只依据 README 文本——未安装、未运行，故不构成对其运行时行为的判定。②「检索质量」与「注入预算」记 1 是无读数档，不是实测结论；README 未提供任何在该两维度上的读数。③多家 Provider 各自的检索/删除/枚举能力 README 声明「differ by backend」，本条未逐家核验。④对本条的判定只对公开可复现的文档表述成立，不对其云端服务的实际行为作判定（未测）。⑤版本面锚在不可变 tag v0.5.28 的 package.json（快照 review/evidence/dsh-mnemon.package.json）。⑥证据 3 是本机复跑，只证明本记录的证据链在本机成立，不构成运行时判定。

未测项（未测 ＋ 原因）

未测 ＋ 原因：①本机未安装、未运行 pnpm verify / node scripts/serve-e2e.mjs——其前置为 Node ^22.19 ＋ pnpm ＋ 完整依赖安装，而本机到 github.com 被 hosts 拦截，无法取依赖。②全部量化维度（hit@k／token 预算／延迟）未取得任何原始输出——README 未公开，故「检索质量」「注入预算」记 1（无读数档）。③多家第三方 Provider 未逐家验证。④--live-model 路径需 DEEPSEEK_API_KEY，本条未提供密钥、未运行。⑤pnpm verify:plugins（scripts/verify-plugin-artifacts.mjs）证明性地需要公网 npm registry 与真实 DSH 运行时：该脚本内明文 fetch('https://registry.npmjs.org/' + name)、npm pack、npm install --registry，并以 --upgrade-registry https://registry.npmjs.org 驱动 scripts/verify-headless-profile.mjs。这与本站「复跑不触网」的约束直接冲突，故本条未运行，也不把它的输出当作任何维度的读数。
