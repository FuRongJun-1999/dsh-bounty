字段含义

五个测评维度

维度查什么为什么
声明面package.json 的 version / peerDependencies / dependencies 区间，与目标宿主版本比0.x 的 caret 语义很窄（^0.17.0 = >=0.17.0 <0.18.0），宿主一升级就可能整行被静默禁用
工具面该包在 request/header.tools[] 里到底注册了几个工具、每轮约多少 token工具面是唯一能证『生效』的权威判据：解析成功、apply 能注册都不算
调用面全库会话日志里该工具名被调用的次数区分『装了没用』与『在用』；但客户端插件不注册模型工具 ⇒ 这一面看不见它们
运行时/结构面bundle 是否命中（目录或 asar）、loader entry id 是否冲突排除加载链上的机械性缺席，避免把『根本没装』误读成『装了没生效』
职责重叠与已装包的职责是否可被替代重叠是摘除的第一依据——但必须拿读数说话，不凭印象

排序规则

本站榜单不做综合加权评分（权重是使用者的资金与偏好，不是站方的），只做多读数并列。排序键与本仓实现 scripts/review_build.py 的 _sort_key() 逐字对应，为两个正交轴 ＋ 一个稳定序：① 可核验的模型工具面成本 —— 读得到（tool_tokens 为数）的排在读不到的前面，同档按 ≈tok/轮 升序；② 证据条目数（升序）；③ 插件 id 字典序（仅用于完全并列时的稳定序，不承载『更好』的含义）。名次只说明『读数是否更完整、代价是否更可核验』，不说明『更值得装』。

离线口径（零网络）

  • 生成器 scripts/review_build.py 纯 Python 标准库；不 import 任何网络模块（socket / urllib / http.client / requests 都禁止）。
  • 生成器不执行证据里的命令——它只把这些字符串渲染进页面；读数在写进 JSON 之前就已采集完毕。
  • 证据的『原始输出』一律是采集时逐字留下的文本，包括命令自身的报错与退出码。
  • CI 只跑生成器与守卫，不发起任何网络请求。

本站不假装知道什么（边界）

  • 工具面统计只覆盖注册模型工具的包；30+ 支客户端插件（含本页的 cost-meter）不注册模型工具 ⇒ 它们的『在用/没用』本站没有数据，不假装有。
  • 体积（MB）是另一支量具的数，本站当前未采集，故不列为维度读数。
  • 版本读数以随仓外附录的行号为准（口径来源：plugin-full-audit-2026-10-11.md；该附录不在本仓，结论性内容已内联进 review/data/plugins.json 各条记录）；本机现读与之不一致时两条并列登记，不择优、不覆盖。
  • 所有证据都有保质期：文档转载的读数标注采集日；跨日使用前应当重跑命令。

怎么复跑

  1. python -X utf8 scripts/review_build.py # 由 review/data/*.json 生成 review/site/*.html（退出码 0）
  2. python -X utf8 tests/test_review_build.py # 守卫：断言全绿（末行「通过 N / 失败 0」）
  3. python -X utf8 tests/test_review_build.py --mutate # 定点变异：每条恰好命中期望红项
  4. python -X utf8 tests/test_review_build.py --list # 只列变异表与期望红项

本页与榜面、详情页一样，全部由 scripts/review_build.py 从 review/data/*.json 机械生成——勿手改 review/site/ 下的 HTML。

本页由 scripts/review_build.py 从 review/data/plugins.json ＋ review/data/method.json 机械生成——勿手改。证据＝命令 ＋ 已采集的原始输出；生成器与 CI 不触网。
