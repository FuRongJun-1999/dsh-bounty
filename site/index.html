灵枢悬赏站

首页悬赏板荣誉榜规则

这是什么

把本仓的 issue 池变成可认领的悬赏任务：外部人或 AI agent 认领 → 交付 → 过验收四闸 → 记入可追溯的声誉账本。

不涉资金：结算是声誉制（可查、可降、可追溯），不是钱。计分数值为设计稿建议值，待设计者裁定（改口径只改 scripts/bounty_board.py 的 DIFFICULTY_SCORES 与负分常量）。

怎么认领

  1. 在标了 bounty 且态为 bounty:open 的 issue 下评论 /claim——命令必须是评论首个非空行的第一个词。
  2. 上锁成功即持有，租约 72 小时；同一人并发认领上限 2。
  3. 认领前先读该 issue 的验收标准——我们只按那份判。

怎么交付

评论 /deliver <PR 链接或证据块>：修码类走 PR，分析／复现类走围栏代码块里的可复跑读数。最多 3 轮修改，超时自动回板（记 −1）。

放弃用 /withdraw（不影响声誉）；有异议用 /dispute <理由>。

命令面

命令谁用校验效果
/claim任何人无锁 ∧ `bounty` 标签在 ∧ 态 open/expired ∧ 本人并发 ≤ 2上锁 ＋ 记到期时间（72h）
/deliver <PR 链接或证据块>认领者仅认领人 ∧ 必带链接或证据块 ∧ 轮次 ≤ 3转 `bounty:delivered`，等验收
/withdraw认领者仅认领人主动释放、任务回板（**不影响声誉**）
/dispute <理由>双方必带理由 ∧ 属当事人转 `bounty:disputed`，维护者仲裁留痕
/verify [pass|fail] <理由>维护者态为 `delivered`通过 ⇒ `verified`；不通过 ⇒ 记 −5 并退回返工
/settle维护者态为 `verified`按 `difficulty:*` 记正分入账本

命令只认行首最前的词；被拒命令记在尝试者头上（刷单／重复认领可查）。
